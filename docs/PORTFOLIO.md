# DevPilot — MCP-Based AI Software Engineering Agent

## Portfolio Summary (62 words)
DevPilot is an autonomous AI software engineering assistant built on the official Model Context Protocol (MCP 2.x) standard and Google Gemini. It investigates codebases, diagnoses test failures, isolates root causes, synthesizes unified diffs, halts for cryptographic human approval, and validates fixes via automated regression testing. Featuring a 10-stage execution pipeline, real-time SSE streaming, and strict sandboxing, DevPilot demonstrates production-grade agentic engineering.

---

## Project Overview

In real-world engineering teams, autonomous coding agents cannot simply generate unverified code or execute unrestricted shell commands. Doing so introduces severe security vulnerabilities, data loss risks, and hallucinations that break existing features.

**DevPilot** was engineered to solve this dilemma. It demonstrates how modern AI-native engineering systems should be architected:
1. **Standardized Tool Integration:** Interacting with repositories exclusively through the **Model Context Protocol (MCP)** rather than arbitrary, unconstrained terminal execution.
2. **Defensive Governance:** Halting automated execution at a human-in-the-loop review gate, enforcing that no source code can be modified without explicit cryptographic token authorization.
3. **Closed-Loop Verification:** Enforcing that a generated patch is never assumed to be correct until baseline failures are proven resolved and zero test regressions occur.
4. **Observable Execution:** Exposing every step of the agent's thought process, tool invocations, and test outputs via real-time Server-Sent Events (SSE).

## 3 Core Engineering Highlights

### 1. Genuine Model Context Protocol (MCP 2.x) Architecture
Unlike typical LLM projects that simulate tool execution through basic Python dictionaries, DevPilot implements the **official Python MCP SDK (`mcp==2.3.0`)**. It spawns an isolated repository MCP server as a subprocess over `stdio` transport, performs JSON-RPC 2.0 handshakes, dynamically discovers 8 registered tools, and executes them with strict parameters and timeouts.

### 2. Cryptographic Human-in-the-Loop Governance
DevPilot enforces the principle of least privilege through an architectural write-guard. The MCP server provides read-only inspection tools (`inspect_repository`, `read_file`, `search_code`, `run_tests`); its code modification tool (`propose_patch`) merely registers a proposed diff and generates a 64-character SHA-256 HMAC authorization token. The system pauses at Stage 8, requiring a human reviewer to confirm the exact token before the backend `ApprovalEngine` applies the patch.

### 3. Closed-Loop Automated Verification Engine
DevPilot validates the core software engineering invariant: *A synthesized diff is not a verified fix.* The agent captures baseline Pytest failures before proposing changes. After human patch approval, the verification engine re-runs the entire test suite, computes delta matrices (fixed tests vs regressions), and marks the fix as verified only when all tests pass with exit code 0.

## Key Technical Challenges & Engineering Solutions

### Challenge 1: Python 3.11 Syntax Incompatibility in Dockerized Environments
- **Problem:** During initial deployment to Railway using `python:3.11-slim`, the backend crashed on startup with `SyntaxError: f-string: unmatched '['`. The local development environment used Python 3.14, which supports PEP 701 (nested identical quotes in f-strings: `f"...{dict["key"]}..."`), whereas Python 3.11 strictly disallows them.
- **Solution:** Performed static AST analysis across the codebase, isolated the offending line in `devpilot/approval/engine.py:48`, and refactored the status lookup into a local variable (`current_status`). Added automated multi-version lint checks to prevent syntax regressions.

### Challenge 2: Protocol Purity vs LLM Schema Quirks
- **Problem:** Google Gemini's Function Calling API rejects certain JSON Schema keys (such as `title`, `$defs`, or complex `additionalProperties` definitions) generated by modern Pydantic v2 models in MCP tools.
- **Solution:** Developed an automated schema normalizer ([`_clean_schema_for_gemini`](file:///c:/Projects/DevPilot/devpilot/agent/orchestrator.py#L40-L75)) that recursively cleans MCP tool definitions into compliant Gemini `FunctionDeclaration` objects while preserving parameter types, descriptions, and required constraints.

### Challenge 3: Eliminating Silent Simulation Fallbacks in Distributed Web Architectures
- **Problem:** Frontend applications often fail silently or mask backend connection dropouts by defaulting to in-browser mocks, misleading reviewers and users.
- **Solution:** Built a transparent connection governance model. The React frontend constantly audits the `/api/health` endpoint. If the Railway backend is unreachable, clicking "Launch Agent" refuses to execute and displays an explicit, high-visibility error alert. Client-side simulation is isolated into a separate, clearly labelled `⚡ Run Offline Demo` action that the user must intentionally trigger.

## Architecture & Technology Decisions

- **FastAPI (Python 3.11):** High-throughput asynchronous REST gateway with native support for Server-Sent Events (SSE) streaming and background task workers.
- **Official Model Context Protocol SDK (`mcp`):** Open, interoperable tool calling standard enabling decoupled subprocess sandboxing over `stdio`.
- **Pytest:** Industry-standard test framework used by the verification engine to capture exit codes, tracebacks, and assertion node IDs.
- **SQLite 3 (WAL Mode):** Embedded, transactional audit trail persisting sessions, 10-stage timelines, tool calls, and cryptographic tokens.
- **React 19 + TypeScript + Vite:** Modern, reactive developer interface featuring a tabbed evidence center, diff viewers, and stage progression indicators.
- **Railway & Vercel:** Distributed cloud architecture pairing low-latency edge static hosting (Vercel) with containerized persistent backend infrastructure (Railway).
